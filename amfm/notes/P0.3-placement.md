# 2. Direction and placement freedom

The old rule — every kind stands on the region's bottom plane — was real, and the
PM's objection was correct: it made every shape grow upwards. Two parameters
replace it, both on the modifier and both persisted:

* `anchor` — which region plane the surface is measured from:
  `Floor` (grows up from the region's bottom face), `Mid` (centred on the region's
  mid plane), `Ceil` (hangs down from the region's top face).
* `closed` — a full barrel / full ellipsoid / all-edge chamfer instead of an
  arch, a dome or a single directed chamfer.

The rule that keeps every kind watertight: **the generated solid is the slab
between the surface and its own anchor plane**, nudged a hair past that plane so
it does not z-fight with the neighbouring cubes. The skirts and the cap always
close against the anchor plane, which is why an arch's end fans, its cap and its
wall still meet exactly at `Mid` and `Ceil`. The alternative — filling from the
surface down to the region floor — leaves the arch's end caps open once the
anchor plane is above the floor, so it was rejected on purpose rather than by
omission. What it costs: a `Ceil` shape is a wedge hanging from the deck, so the
region you select is the region that gets replaced. That is the same "the region
becomes the solid" model the slope already had, now in three directions.

`rise` keeps its single meaning for all four kinds: distance away from the anchor
plane. Dragging the handle inverts correctly per anchor (`rise = (world_z - base)
* dirz`, or `|world_z - centre|` for a shape centred on its anchor).

`closed` only changes the vertical extent for Cylinder and Sphere. For Bevel it
selects the edge set (all four edges of the face versus the single edge at the
high end of the run — the directed bevel). For Slope it changes nothing. The
frame computes this once as `spans`, so the handle, the geometry and the tests
cannot disagree about it.

# 3. Voxel edits inside a shape's own region

The surface is generated from the **region box**, not from whichever cells happen
to be inside it. So a voxel painted inside a shape's region cannot move the
surface — and silently ignoring it would be the actual defect. The modifier now
records `applied_hash`, the hash of its own layer's cells inside the region at
Apply time, and re-checks it a few times a second while a shape session is open
(hashing a 148k-cell layer every frame is not free, so it is throttled). On a
mismatch the strip says so in words:

> Cells inside this region changed after the shape was applied; the surface
> follows the region, not those cells

The self test drives this directly on the real asset:

* adding a cell inside the region **is reported**;
* the surface **does not ghost** to it — the mesh hash is bit-identical before
  and after (`mesh 3845648702 -> 3845648702`), so there is no half-updated shell;
* recolouring inside the region **stays reported**;
* removing the added cell **clears the report**, i.e. the check is a diff against
  a baseline and not a one-way latch.

Traceability is checked rather than inferred: for the shape layers, the generated
surface's horizontal footprint must equal its source region to within the
anti-z-fighting epsilon (`Slope 1: x -60.00..-43.00 y -5.00..6.00`,
`Bevel 2: x 40.00..64.00 y -34.00..34.00`). A rendered face therefore maps to a
named region of source cells, which is the thing the PM asked not to assume from
a preserved total count.

# 4. Stress with memory instrumentation

`GOXEL_STRESS=<cycles>`, run at 120 cycles in `evidence/stress/stress.log`:

* **Phase A** builds and releases the heaviest configuration this module can make
  — every kind × every anchor × open/closed, 24 meshes per cycle, **2,880 meshes,
  peak 3,312 vertices** — with `_heapchk()` after every cycle. Heap intact.
* Every mesh this module allocates is counted in and out (`s_mesh_live`). After
  phase A the live count is **exactly back to its baseline** (`live +0 of 2907
  made`), so nothing generated is leaked.
* **Phase B** churns the real document's undo stack under the modifiers
  (rise bump → history push → undo → redo), 120 times, heap-checked each time.
  Heap intact, and the document's cell count is unchanged
  (`148,382 of 148,382`).

Two things this caught about the *test*, not the code, and were fixed rather than
worked around: comparing the live count across an undo churn is meaningless
because undo legitimately frees meshes that existed before the loop, and a churn
that ends on `undo` leaves the document one step behind, which fakes a cell
change. Both phases are now written so the numbers mean what they say.

Save/reopen now also proves the new fields survive: one modifier is deliberately
given `Mid` + `closed` before the save, and the reopened document is compared
field by field (`reopen keeps the anchor plane and open/closed shape -- 4 of 4
modifiers`).

# Defects found and fixed in this pass

1. **Stack overrun in the handle-drag path.** `vec3_set(win, mx, my, 0)` wrote
   three floats into `float win[2]` — the same class of bug as the earlier
   `model_vertex_t.uv` overrun, this time in screen space, and it was smashing an
   adjacent local. `-Warray-bounds` caught it. Now `vec2_set`.
2. **Cancel did not restore the new parameters.** `slope_saved_t`, the snapshot a
   Cancel rolls back to, still only carried aabb/kind/dir/rise, so changing the
   anchor plane or the open/closed shape and pressing Cancel left them changed.
   Both fields are now saved and restored.
3. **`slope_free` leaked the mesh's CPU memory** whenever the graphics were not
   initialised, because the whole delete was behind a `graphics_initialized`
   guard. Only the VBO needs a context; the CPU side is now always freed.
4. **Harness, not product:** the helper scripts piped `scons` through
   `grep -E 'error|…' | head -20`. Every compile line contains `-Wno-error`, so
   `head` exited early, SIGPIPE killed `scons` mid-build, and the script happily
   ran a **stale binary** — which is why a brand-new demo appeared to ignore its
   own environment variable. The scripts now build to a log, check the exit
   status, and grep for `error:` only.
