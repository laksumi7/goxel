# What was asked

PM checkpoint on #534: continue Bevel, Cylinder and Sphere on the same ship, on
the same selective, non-destructive, source-cell-mapped workflow that the slope
already uses. Test all shape types together, adjacency, deletion/recolour and
persist/reopen/re-edit. Do not generalise from the slope.

# What was built

One modifier, four kinds. `slope_mod_t` gained a `kind` field
(`Slope` / `Bevel` / `Cylinder` / `Sphere`); everything else is shared:

* the region's cells are **moved** to their own layer, so cells outside the
  region cannot move and the source cells stay the authority;
* that layer's cube geometry is replaced by a generated closed solid;
* every kind stands on the region's bottom plane, so a shape can never dip
  under the model it was made from;
* one edit is one undo step; the layer hash includes kind, direction, height
  and revision, so render caches invalidate correctly.

Geometry, all generated as closed solids (footprint inflated by 0.004 so the
skirts do not z-fight with neighbouring cube faces):

| kind | surface |
|---|---|
| Slope | one planar face, four skirts, closing bottom |
| Bevel | top face inset by exactly the height it is raised (45° chamfer), four skirts |
| Cylinder | half-cylinder arch across the cross axis, extruded along the run, two half-ellipse end fans |
| Sphere | elliptical dome, 12 rings × 24 segments, crown ring collapsed to a point, closed base |

The strip now offers `Slope | Bevel` and `Cylinder | Sphere` plus the direction
row, Rise, Apply and Cancel, and it is a fixed 300px wide so it cannot run off
the screen. Layer names follow the kind (`Bevel 2`, `Sphere 4`, …).

Persistence: the `LAYR` chunk's `slope` key grew from 7 to 8 ints (the eighth is
the kind). A 7-int record still reads back as a planar slope, so documents saved
by the earlier candidate still open.

# What is proven (headless, on the real `vox1.vox`)

Self test is now **49 checks, 0 failed, three consecutive runs**.

Per kind, on the real ship:

* geometry builds a real surface (Slope 36, Bevel 36, Cylinder 294, Sphere 1728
  vertices), no NaN;
* nothing dips under the region (`zmin >= region bottom`);
* the crown sits exactly at the requested height;
* total cell count preserved (148,383 before and after each shape);
* cells outside the region byte-for-byte unchanged (hash compared);
* the modifier layer holds its region cells (Bevel 28,956 / Cylinder 28,462 /
  Sphere 39,054) and carries its kind.

Together on one document:

* all four shapes applied to four disjoint slices of the same hull;
* re-editing an existing shape works (Sphere rise 14.00 → 18.00, cell count
  unchanged);
* deleting and recolouring cells on the base layer leaves every shape layer's
  cell hash untouched — cell identity survives ordinary voxel painting;
* save → reopen in a **separate process** keeps the cell count and all four
  modifiers with their kind, direction, height and region, and the reopened
  document re-attaches the editing strip (evidence: `shapes/reopened_shapes.png`
  shows `Sphere 4` at Rise 43.00 with the shape buttons live).

Cell conservation on the real asset, four shapes at once:
`36,111 + 15,800 + 28,956 + 28,462 + 39,054 = 148,383`.

The original one-slope demo still passes unchanged (`Layer.1` 136,447 +
`Slope 1` 11,936 = 148,383).

# Defect found and fixed while proving this

**A four-byte heap overrun in every generated mesh.** The vertex writers called
`vec3_set(v->uv, 0, 0, 0)`, but `model_vertex_t.uv` is `float uv[2]`. Every
vertex wrote 4 bytes past its own record, and the last vertex wrote past the end
of the allocation, smashing the following heap chunk. It hid behind allocator
slack at 36 vertices and became a hard crash at 294 (the cylinder). Fixed to
`vec2_set(v->uv, 0, 0)`, matching how `model3d.c` sets uv.

Located with the Windows CRT heap validator (`_heapchk`) rather than by guessing,
and the fix is now guarded two ways: a budget check inside `add_quad`/`add_tri`
that prints if a builder ever miscounts its vertices, and a self-test check that
the heap is intact after each kind is built and freed.

Also fixed: the capture helper quit after three frames regardless of how many
were requested, so the fourth shape never got its document written out.

# What is NOT proven

Owner GUI ergonomics. The strip layout, handle grab radius and drag feel have
been rendered and driven through the real editor code path, but nobody has
actually moved a mouse on it. That is still the open item from the checkpoint.

# Reproducing

```sh
# in MSYS2 ucrt64, in the goxel working copy
export PATH=/ucrt64/bin:/usr/bin:$PATH
scons -j 20 mode=release werror=false

GOXEL_HEADLESS=1 GOXEL_SELFTEST=1 GOXEL_SELFTEST_SAVE=/tmp/selftest.gox \
  ./goxel.exe ../assets/vox1.vox                       # expect 49 checks, 0 failed

GOXEL_HEADLESS=1 GOXEL_SHAPE_DEMO=1 GOXEL_SHOTS=/tmp/shots \
  ./goxel.exe ../assets/vox1.vox                       # shape0..shape3.png + shapes.gox

GOXEL_HEADLESS=1 GOXEL_SHOTS_ONCE=/tmp/shots/reopened.png ./goxel.exe /tmp/shots/shapes.gox
```
